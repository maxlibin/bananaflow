# CLAUDE.md

Guidance for AI coding agents working in this repository.

## Commands

```bash
yarn dev            # Next.js dev server (Turbopack)
yarn build          # Production build
yarn lint           # ESLint
yarn typecheck      # tsc --noEmit
yarn test           # node:test suites under scripts/test-*.ts (sequence actions need docker compose Postgres)
yarn test:e2e       # Playwright in Chrome against yarn dev -p 3100 (Postgres + .env)
yarn db:generate    # Drizzle migration from src/db/schema.ts
yarn db:migrate     # Apply migrations
docker compose up -d  # Local Postgres
```

`postinstall` runs `scripts/patch-filerobot-react-imports.mjs`, which patches `react-filerobot-image-editor` for React 19. The package is pinned to an exact beta because newer betas already carry the import in some files.

## Architecture

Single Next.js 16 app that is also an npm package (`bananaflow`) consumed by the hosted product. Every file under `src/` uses **relative imports only**; a `@/` alias would resolve against the consuming app when this repo is installed from git.

- **Canvas** `src/components/flow/**`, `src/stores/board-store.tsx` (Zustand store per board), `src/stores/board-tabs-store.ts`. Node types: `inputNode`, `outputNode`, `videoNode`, `seedNode`, `upscaleNode`, `removeBgNode`, `faceConsistencyNode`, `scriptNode`, `shotNode`, `entityNode`, `sequenceNode` (legacy `promptNode`, `imageNode` still render).
- **Script writing** `src/lib/script/*` (pure: Plate document types, story structures, scene extraction + hashing, timing, shot-to-prompt compiler per video model family, shot graph layout), `src/components/script/*` (Plate editor with screenplay blocks, script panel, guided start, script doctor), `scriptNode` / `shotNode`. A Script node's `doc` is a Plate value; Entity nodes (character / product / location: name, look, reference images, optional generated reference sheet) belong to a script; `scriptAssistant.extractEntities` finds them. "Break into shots" asks `scriptAssistant.breakIntoShots` for a plan tagged with entity names, and `applyShotPlans` lays out Shot → Keyframe (output node on `CanvasModels.referenceImageModel`) → Video per shot: tagged entities feed the keyframe's `input`, the shot feeds both (image nodes read its `stillPrompt`, video nodes its motion `value`), and the keyframe is the video's first frame via `images`. Shots of the same scene + order update in place, so keyframes and videos keep results, and entity wires re-sync. Output and video nodes keep images per handle (`connected-images.ts`) so `input` and `images` combine. A shot's `sceneHash` marks it stale when its scene text changes. All AI help comes through `CanvasHost.scriptAssistant`, built by `createScriptAssistant` (`src/lib/script/create-script-assistant.ts`) from the script server actions in `src/lib/actions/script.ts`. Those use the prompts and schemas in `src/lib/script/ai/*`; `generateScriptObject` asks `policy.beforeText`, calls `generateText` on `host.text.languageModel(userId, modelId)`, then reports usage to `policy.afterText`. Failures return `{ ok: false, error, denial }` because server action errors are redacted in production. A host without an LLM can pass `null` and the editor works without AI. Plate UI files in `src/components/ui/` come from the Plate shadcn registry (`@plate` in `components.json`), with imports rewritten to relative paths.
- **Direction presets** `src/lib/direction/presets.ts` (camera moves, lenses, looks, lighting: label, description, prompt phrase) and `src/components/direction/direction-picker.tsx` (chip + popover gallery). Shots store `cameraMove`, `lens` and optional `look` / `lighting` overrides; Script nodes hold the script-wide `look` / `lighting`; `compileShotPrompt` / `compileStillPrompt` resolve them into prompt phrases. Input nodes insert a preset's phrase into their prompt text. Hosts can attach sample media per preset through `CanvasHost.directionSamples` (keyed by `directionSampleKey`); without one the picker shows the description.
- **Canvas host** `src/components/canvas-host/context.tsx`. Client components never import server code; they read `actions` (server-action wrappers), `costPreview`, `onLimit`, `onGenerationSettled`, `track`, `scriptAssistant` and `directionSamples` from `useCanvasHost()`.
- **Engine** `src/lib/**`. Provider adapters (`lib/providers/{openai,google}.ts` behind the `Provider` interface in `lib/providers/types.ts`: `info` describes the provider, `editingModel` names the model used by upscale / remove-bg / face consistency, `createImageTask` / `createVideoTask` return a synchronous result or an async task id, `describeVideoTask` reports the length, price tier and audio the video request will produce, `fetch*Task` and `parse*Callback` return a normalised `TaskStatus`), model descriptions (`model-registry.ts` for the server side: provider + providerModel + capabilities; `model-options.ts` for the client side: picker entries and per-model setting options), job helpers (`image-jobs.ts`, `video-jobs.ts`: `applyImageTaskStatus`, `completeImageJob`), action implementations (`lib/actions/*`, first parameter is always `host`), route-handler factories (`lib/routes/*`, `createXxxRoute(host)`), scheduler functions (`lib/scheduler/*`), storage implementations (`lib/storage/*`), key encryption (`lib/keys/*`).
- **Host adapter** `src/lib/host/types.ts`. `HostAdapter` = `{ db, auth, providers.list, models, text, keys, policy, limits, storage, callbacks }`. `text` lists the script-writing models (`models`, `defaultModelId`, `fastModelId`) and resolves an AI SDK `LanguageModel` per user; `policy.beforeText` / `afterText` gate and meter each LLM call. `providers.list` is the ordered list of `Provider` objects a deployment offers and `models.image` / `models.video` the models it exposes; advanced ops use the first listed provider whose editing model is in `models.image`. Only `src/app/**` and `src/host/**` may import the `host` singleton from `src/host/index.ts`; engine modules receive it as a parameter. A `Denial` from the host becomes an HTTP response via `denialResponse()` or an action result via `denialActionResult()`.
- **Local host** `src/host/local/*`: user id is always `"local"`, providers are `google` then `openai` with every model from both, text models are GPT-5.6 (OpenAI key) and Gemini (Google key) via `@ai-sdk/openai` / `@ai-sdk/google`, policy allows everything, keys come from the `provider_keys` table (AES-256-GCM with `APP_SECRET`) then the provider's env var (`provider.info.envVarName`), storage is local disk or S3, callbacks use `PUBLIC_BASE_URL` or null.
- **Database** `src/db/schema.ts` (Drizzle, bare `pgTable`), `src/db/index.ts` (node-postgres pool). `updatedAt` columns set their value JS-side on every insert/update.
- **Scheduler** `instrumentation.ts` starts `src/lib/scheduler/in-process.ts` when `ENABLE_INPROCESS_SCHEDULER=true`. The same functions back `/api/cron/*`.

## Generation pipeline

1. Route factory: `host.auth.getUserId()`, validate body, look the model up in `host.models.image` / `host.models.video`, resolve its provider with `getProvider(host, info.provider)`. Video settings go through `resolveVideoSettings` (only the fields in the model's `settings` options, each checked against its allowed values; 400 otherwise), and `beforeGenerate` bills the provider's `describeVideoTask` of those same settings. Optional `shots` (multi-shot, from connected Shot nodes when the model's options have `multiShot`) and `lastFrame` (the video node's `lastFrame` handle, when `supportsLastFrame`) are checked by `resolveVideoShots` / `checkLastFrame` and passed to the provider; billing uses the shots' total length.
2. `host.keys.resolveProviderKey(userId, info.provider)`; `host.callbacks.publicBaseUrl()` (null means no webhook).
3. `host.policy.beforeGenerate(...)` (no-op locally, returns a `Denial` in hosted products).
4. Insert the job row, `provider.createImageTask(...)`. Reference images are built by `buildReferenceImages(host, urls)`: a public URL for URL-taking providers, lazy bytes (via `host.storage.resolveAssetUrl`) for the rest.
5. Synchronous result: `completeImageJob` at once, respond `status: "completed"`. Asynchronous: store the task id; the poller (or a provider webhook bound through `lib/routes/provider-webhooks.ts`) calls `applyImageTaskStatus` with the normalised status.
6. `completeImageJob`: materialise assets, `host.storage.uploadAsset`, persist media, `adjustBoardStorage`, `host.policy.afterGenerate(...)`.

Jobs settle exactly once: completing, failing and cancelling (`markImageJob*` / `markVideoJob*`) are compare-and-set updates from `pending`/`processing`, and only the caller that wins refunds (`failImageJob`, `cancelImageJob`) or delivers. A completion that loses the race deletes the media it saved, so a cancel can never end with both a refund and an image.

## Sequence export

A `sequenceNode` orders connected video/output/image/input nodes into a cut (edges decide membership; `items` keep order, trims and still hold times). The edit model is `lib/sequence/model.ts`, "Assemble cut" (Script panel) is `lib/sequence/assemble-cut.ts`, and `lib/sequence/render.ts` renders the MP4 in the browser with Mediabunny (1080p at the node's aspect ratio, 30 fps, H.264 + AAC 48 kHz stereo, letterboxed on black; clip audio is converted to that format, silence fills stills and silent clips). Export: `createExportUpload` (quota via `host.limits.canStore`, key `<userId>/sequences/<boardId>/<id>.mp4`) → browser PUT to `host.storage.createUpload`'s URL → `saveSequenceExport` (checks key prefix and stored size via `getAssetSize`, writes the media row, updates storage). Local disk uploads go to `/api/uploads/[...key]` with a token signed by `APP_SECRET`; S3 uses presigned PUTs. `/uploads/*` serves byte ranges so browsers can read and seek MP4s.

Voiceover: one narrator per sequence (`voice: { model, voiceId }`); each item may carry a `voiceover` line, pre-filled from the Shot node feeding its clip (`shotVoiceLines`). `lib/sequence/voiceover.ts` owns the rules: `voiceoverStatus` (none, unvoiced, stale when the text or voice changed, too-long when the audio outlasts the item, ready), `validateSequence` blocks export on anything but none/ready, and `duckingGain`/`mixVoice` lower clip audio to `DUCK_LEVEL` (0.25, 150 ms ramps) under the line in both the preview and the export. Lines are voiced one at a time through `/api/generate-speech` (`createGenerateSpeechRoute`): board ownership, text and voice checks, `host.policy.beforeGenerate({ kind: "speech" })`, `Provider.createSpeech`, length measured with Mediabunny, stored via `host.storage.uploadAsset` as an `AUDIO` media row, then `afterGenerate`. Speech models live in `model-registry.ts` (`OPENAI_SPEECH_MODELS`, `GOOGLE_SPEECH_MODELS`); hosts list theirs in `HostAdapter.models.speech` and `CanvasModels.speech`.

Adding a model: add a server entry to `model-registry.ts` (provider + providerModel + capabilities) and a client entry plus setting options to `model-options.ts`; the local host composes both in `src/host/local/providers.ts`. Adding a provider: implement `Provider` in `lib/providers/` and add it to `LOCAL_PROVIDERS`.

## Conventions

TypeScript everywhere, double quotes, trailing commas on multi-line. Components PascalCase; `src/lib` files hyphenated. Bigints stay bigint until serialized. Don't use native `alert`/`confirm`; use `notifyDialog` / `confirmDialog` from `src/components/ui/dialog-host.tsx`.
